# WH 后台后续优化建议文档

日期：2026-06-10

## 1. 总体判断

当前后台已经具备 WH 截图功能的主要可用链路：菜单、页面、表格、搜索、分页、排序、弹窗、行按钮、核心业务 API、审计和数据库持久化已经打通。

后续优化重点不应推翻现有框架，而应继续沿用当前 Spring Boot + MyBatis-Plus + PostgreSQL + React/Vite 管理后台，在现有模块内分阶段增强。

## 2. P0：安全与权限执行链

### 2.1 数据权限落到查询条件

当前已经有角色数据范围配置能力。建议下一步把数据范围真正接入更多查询服务：

- 用户列表：按部门、角色、自定义范围限制可见用户。
- 账户列表：按用户可见范围限制账户。
- 订单、持仓、成交：按用户、账户或部门数据范围过滤。
- 资金流水、充值、提现：按用户数据范围过滤。
- 日志：只允许高级管理员看全量请求日志。

实现建议：

- 新增 `AdminDataScopeResolver`，把当前管理员 ID 转换成可用的数据范围对象。
- QueryService 入参增加 actor 信息，统一调用数据范围 helper。
- 不在前端隐藏数据作为权限手段，后端必须做最终限制。

### 2.2 高风险按钮二次确认

以下操作建议增加二次确认、原因必填、审计详情扩展：

- 产品下架。
- 风控价格调整。
- 用户冻结、强制退出、登录失败次数重置。
- 资金入金、扣款、余额调整。
- 充值/提现审核。
- 订单撤销、强平、挂单成交。

实现建议：

- 复用 `AdminReasonRequest`。
- 前端通用弹窗里对高风险 action 显示原因字段。
- 后端审计详情保存 before/after、reason、operator、requestId。

## 3. P1：WH 视觉与交互还原

### 3.1 后台壳层

建议继续增强这些截图细节：

- 顶部多标签左右滚动、关闭左侧、关闭右侧、关闭其他。
- 头像下拉菜单、个人中心、退出登录。
- 通知铃铛弹窗和未读数量。
- 九宫格快捷入口。
- 左侧菜单完全折叠时只显示图标，并保留 tooltip。

### 3.2 表格工具栏

当前已经有刷新、搜索、设置、导入、导出、批量操作任务。建议继续增强：

- 打印按钮生成当前表格打印视图。
- 搜索图标展开/收起高级搜索区。
- 表格列拖拽排序后保存列顺序。
- 固定列：左固定、右固定真正作用到表格布局。
- 表格边框、斑马纹、密度设置本地和服务端保持一致。

### 3.3 树表和抽屉

权限菜单、部门、产品分类更适合树表：

- 增加展开/折叠全部。
- 父子级联选择可配置开关。
- 菜单编辑可改为右侧抽屉，贴近截图体验。

## 4. P1：上传和富文本

截图中多处涉及上传和富文本：

- 个人头像上传。
- 充值凭证上传。
- 用户实名正反面图片。
- 产品介绍富文本。
- 系统底部导航、协议、服务条款富文本。

建议：

- 继续使用现有上传配置表，不另建上传框架。
- 后端新增统一 `AdminFileController`，按当前上传模式限制文件类型和大小。
- 前端抽出 `ImageUploadField`、`RichTextField`，让产品、公告、新闻、通知、系统设置复用。
- 富文本保存前做白名单清洗，防止后台内容进入前台时产生 XSS。

## 5. P1：导入导出异步化

当前导入/导出已创建真实任务，但还没有真正生成文件。

建议阶段：

1. 导出任务创建后写入 `PENDING`。
2. 后台调度器读取任务并生成 CSV/XLSX。
3. 成功后写入 `fileUrl`、成功行数、失败行数。
4. 失败时写入错误信息。
5. 前端轮询任务状态并显示下载按钮。

实现注意：

- 大表导出必须分页读取，避免一次性加载全部数据。
- 导出字段必须使用表格列配置，而不是直接导出 Entity。
- 导入必须先做 dry-run 校验，再批量写入。

## 6. P1：业务字段补强

为了更贴近 WH 截图，可以在不破坏交易核心表的前提下增加管理扩展表。

### 6.1 产品管理扩展

建议新增 `market.symbol_admin_configs`：

- 产品代码2。
- 倍数列表。
- 默认倍数。
- 每手。
- 费率。
- 是否设置。
- 产品说明富文本。
- 风控增量。
- 风控计数。
- 上次风控设置时间。

交易核心字段继续留在 `market.symbols`，后台展示字段从两张表聚合。

### 6.2 充值/提现快照

建议给资金订单补充或扩展：

- 订单号。
- 实到金额。
- 费率。
- 手续费。
- 凭证图片。
- 钱包地址。
- 地址网络。
- 审核人。
- 审核时间。
- 审核备注。

这样可以完整复刻截图表格，不需要从备注字段里解析。

### 6.3 用户实名资料

建议把实名图片、证件号、真实姓名、手机号、邮箱、注册 IP、登录失败次数、安全密码状态等字段聚合成专用后台 DTO，避免用户列表页面字段分散。

## 7. P2：自动化测试沉淀

建议把本轮的一次性定向联调脚本沉淀成正式脚本：

- `scripts/smoke-admin-wh-gap.mjs`
- 覆盖产品、收款方式、公告、新闻、通知、订单、资金、表格设置。
- 每个步骤都输出 PASS/FAIL 和关键 ID。
- 支持 `API_BASE_URL`、`ADMIN_SMOKE_EMAIL`、`ADMIN_SMOKE_PASSWORD` 环境变量。

前端建议补充 Playwright 或 Browser 自动化：

- 登录后台。
- 打开产品列表。
- 搜索新增产品。
- 打开编辑弹窗。
- 保存并验证表格刷新。
- 打开表格设置并保存列配置。

## 8. P2：代码可维护性

### 8.1 前端字段配置拆分

`adminApi.ts` 中页面字段、列、payload mapper 已经开始变多。建议后续按 pageKey 拆分：

- `services/featurePages/rbacFeaturePages.ts`
- `services/featurePages/marketFeaturePages.ts`
- `services/featurePages/financeFeaturePages.ts`
- `services/featurePages/contentFeaturePages.ts`

保持 `adminApi.ts` 作为统一出口，避免页面层感知多个 service。

### 8.2 后端查询 helper 扩展

`AdminFeatureQuerySupport` 可以继续补：

- 日期范围：`filter.createdAtStart`、`filter.createdAtEnd`。
- 数字范围：金额、手数、余额。
- 枚举值归一化：中文状态到系统状态值。
- 多选条件：逗号分隔或数组格式。

### 8.3 审计详情结构化

当前审计详情建议从字符串逐步升级为结构化 JSON：

- `reason`
- `before`
- `after`
- `targetName`
- `requestId`
- `pageKey`
- `actionKey`

这样后续请求日志、操作日志和风控追踪可以更好联动。

## 9. 不建议做的事

- 不建议新建第二套 Java 后台。
- 不建议把业务写接口塞进通用 `feature_records` 假 CRUD。
- 不建议为了截图字段把交易核心表改成大而全表。
- 不建议在前端本地过滤替代后端查询。
- 不建议实现隐蔽控价或不可审计的价格操控。

## 10. 推荐下一步顺序

1. 数据权限执行链。
2. 上传和富文本字段组件。
3. 导入导出真实文件生成。
4. WH 产品管理扩展表。
5. 资金订单凭证和审核快照。
6. 表格固定列、打印、列拖拽。
7. 正式 E2E 脚本沉淀。

这条路线能继续保持现有代码风格和架构边界，同时把 WH 截图体验从“功能可用”推进到“体验和字段细节高度贴近”。
