# 看得懂的交易场景测试报告设计

## 目标与读者

把现有 191 个 Spot + USDT 线性永续 DEMO 场景，从工程字段翻译成非技术读者能直接理解的交易过程。读者应能回答：在什么价格、以什么方向、成交多少、产生多少手续费和盈亏、验证了哪条算法、最终是否符合预期。

主要读者是产品负责人、业务验收人员和交易规则评审者，不要求理解 Java、JUnit、数据库表或 Oracle 实现。

## 证据边界

- 场景定义：`docs/testing/spot-perp-scenario-matrix.json`
- 实际执行证据：`backend/target/scenario-artifacts/<caseId>/actual.json`
- 总体通过状态：`docs/testing/spot-perp-test-report.md`
- 价格、数量、成交、手续费、钱包、仓位、盈亏、资金费和失败码均从上述文件读取，不手工编造。
- 当前矩阵实际交易品种是 `BTCUSDT` / `BTCUSDT-PERP`。没有 ETH 成交证据时，报告不得把 BTC 示例改写为 ETH。
- 真实 partial fill 与 DEPTH matching 不在本矩阵范围内；`PARTIALLY_FILLED` 仅验证兼容输入被安全拒绝。

## 采用的展示方案

采用“代表案例 + 全量分类明细”的混合报告：

1. 顶部用简明结论说明 191 个场景全部通过，以及 Spot、Perpetual、成功路径、预期拒绝路径的数量。
2. 展示两个真实代表案例：`SPOT_SELL_PROFIT` 和 `PERP_CLOSE_PROFIT`，逐步解释成交与盈亏。
3. 全部 191 个案例按九类放入表格，每一行是一条可以独立阅读的测试用例。
4. 每行固定显示：编号、场景、交易条件、交易过程、盈亏/资金影响、验证算法、测试结果。

不采用纯卡片墙，因为 191 张卡片难以浏览；不采用只有英文 caseId 的原始表格，因为不能满足“看得懂”的目标；不只选代表案例，因为会丢失完整验收范围。

## 九个业务分类

1. 现货基础买卖与盈亏
2. 现货挂单、止损与 OCO
3. 现货风控、幂等与并发
4. 永续开仓、加仓、减仓与平仓
5. 永续挂单与订单生命周期
6. 永续保证金、杠杆与仓位模式
7. 永续资金费
8. 永续止盈止损、强平与破产保护
9. 永续风控、幂等、权限与并发

分类由产品类型、caseId 和动作类型确定；每个 caseId 必须且只能进入一个分类。

## 单条测试用例的信息结构

- **场景**：中文名称 + 原始 caseId，便于业务阅读和工程追踪。
- **交易条件**：品种、仓位方向、逐仓/全仓、杠杆、订单类型、价格路径。
- **交易过程**：按 action checkpoint 顺序列出新增成交；成交必须包含方向、数量、价格和手续费。没有成交的资金费、改单、撤单、触发或拒绝动作按实际状态描述。
- **盈亏/资金影响**：
  - Spot 显示已实现盈亏、未实现盈亏、按资产汇总的手续费，以及各钱包最终总额和相对初始余额的变化。
  - Perpetual 显示已实现盈亏、未实现盈亏、资金费、交易手续费、最终余额/权益/占用保证金，以及最终余额相对初始 USDT 的账户余额变动。
  - 预期拒绝场景显示错误码，并明确被拒动作不得产生额外成交或非法资金/仓位变化；若此前已有合法成交或并发赢家，仍展示最终实际手续费与盈亏，不能把合法影响隐藏成“零变化”。
- **验证算法**：用自然语言给出该场景对应的核心公式或状态机约束。
- **测试结果**：统一显示“测试成功”；预期拒绝场景显示“按预期拒绝，测试成功”。

## 盈亏解释口径

- Spot 买入：`净收币 = 毛买入量 - base 手续费`。
- Spot 卖出：持仓已实现盈亏采用系统实际值；买入 base 手续费已进入含费成本，卖出 quote 手续费从卖出收入扣除。
- Perpetual 已实现盈亏：多仓为 `(平仓价 - 开仓均价) × 平仓数量`，空仓方向相反。
- Perpetual 账户余额变动：`最终账户余额 - 初始 USDT`，因此包含交易盈亏、交易手续费、资金费、强平费及系统实际结算影响；未实现盈亏另看最终权益，不能混入余额变化。
- 未实现盈亏使用最终仓位快照；资金费现金流只汇总最终账本中 `type = FUNDING_FEE` 且 `referenceType = FUNDING_SETTLEMENT` 的记录，避免把强平时仓位资金费重分类重复计入。

## HTML 结构

生成一个自包含 HTML 文件，使用 Data Analytics 的 canonical report artifact renderer：

- 标题
- Executive Summary
- 关键统计
- 两个代表案例
- 阅读口径
- 九类全量测试表
- 下一步使用建议
- 范围与假设

同时保留 canonical `artifact.json`，让 HTML 中的每张指标卡和每个表格都能追溯到矩阵、actual evidence 或最终测试报告。

## 验收标准

- 恰好覆盖 191 个唯一 caseId：Spot 36、Perpetual 155。
- 恰好覆盖 163 个成功路径、28 个预期拒绝路径。
- 每条记录的交易过程、盈亏说明、算法说明和结果均非空。
- `SPOT_SELL_PROFIT` 必须显示买入价 `110.51105000`、卖出价 `119.48805000`、已实现盈利 `8.86197280 USDT`。
- `PERP_CLOSE_PROFIT` 必须显示开仓价 `110.51105000`、平仓价 `119.48805000`、交易盈亏 `8.97700000 USDT`、扣费后净资金增加 `8.86200044 USDT`。
- 382 个 expected/actual JSON 仍可解析；生成过程不修改原始证据。
- HTML 打包验证阶段为 `passed`；若只能 structural-only，必须明确报告浏览器 QA 限制。
- 不提交、不暂存、不创建分支。
