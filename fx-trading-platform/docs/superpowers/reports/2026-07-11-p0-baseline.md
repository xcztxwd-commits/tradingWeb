## 4. Docker/PostgreSQL/Redis 基线

执行 Docker Desktop 隐藏启动后：

    docker version
    docker compose -f infra/docker-compose.yml up -d
    docker compose -f infra/docker-compose.yml ps

结果：失败。Docker client 可用，但 `desktop-linux` engine 对 version、image 和 container API 均返回 HTTP 500。`wsl.exe --status` 表明当前 Windows 主机未具备可用 WSL Linux 环境；因此本阶段无法启动 compose 中的 PostgreSQL 16/Redis 7。

处理原则：

- 不擅自安装 Windows 可选功能或要求主机重启。
- 先执行不依赖容器的单元测试与实现。
- 所有 PostgreSQL/Flyway/真实浏览器验收保留为最终强制门禁；环境恢复后必须补跑，不能用 H2 或 mock 冒充通过。

## 5. Git hook 基线

首次正常提交时，`pre-commit` 的外层 ESLint 成功，随后现有 `.husky/commit-msg` 因只有 `npm run commit-lint`、没有可执行脚本头而报 `cannot spawn .husky/commit-msg`。文档基线提交在已确认 ESLint 成功后使用一次 `--no-verify`；后续提交继续先显式运行对应验证，并记录 hook 状态。

## 6. 基线结论

现有 Java 单元测试、Web/Admin 等价测试和架构门禁全部通过。已知的既有环境/脚本问题只有：Docker Linux engine 不可用、Windows Node glob 脚本失效、外层 pnpm frozen-lock 配置不一致、Husky commit-msg 不可执行。它们不会被混入业务功能修改；数据库和真实浏览器验收仍是完成声明前的硬性未决项。
