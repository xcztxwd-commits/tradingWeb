# WH 后台后续优化建议

日期：2026-06-10

## 建议优先级

1. 数据权限进一步细化
   - 当前已具备角色数据范围配置和保存能力。
   - 下一步建议将 `DEPARTMENT`、`SELF`、`CUSTOM` 范围接入更多后台查询条件，尤其是用户、账户、订单和财务列表。

2. 导入/导出任务异步执行
   - 当前已落库任务并能从前端创建。
   - 下一步建议增加 worker 或调度器，异步生成 Excel/CSV 文件并写入 `file_url`、成功/失败行数。

3. FeatureCrudPage 表单体验增强
   - 当前统一页面已接入真实 API 和表格偏好。
   - 建议对不同页面增加更明确的字段类型，例如时间选择、金额格式化、枚举下拉、用户选择器、产品选择器。

4. 审计与请求日志归档
   - 请求日志和验证码日志已经落库。
   - 建议增加保留周期、冷热归档和按时间分区，避免日志表长期增长影响查询。

5. RBAC 权限执行链
   - 当前角色、菜单、按钮权限可以配置。
   - 建议继续将按钮权限接入前端按钮显示控制和后端 `@PreAuthorize` 或自定义权限注解。

6. API 文档完善
   - Knife4j 依赖已存在。
   - 建议补充接口分组、请求示例和响应示例，形成后台管理 API 手册。

7. 前端端到端测试沉淀
   - 本次已用 Playwright 做真实联调。
   - 建议将关键后台链路固化为可重复运行的 E2E 脚本，覆盖登录、RBAC、资金审核、会员 KYC、日志和表格工具。
