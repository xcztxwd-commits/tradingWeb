# WH 外汇后台截图功能与当前项目代码缺口审计

生成日期：2026-06-10

范围：只分析用户提供的 WH 外汇后台截图、仓库内已有 WH 功能说明文档，以及当前 `fx-trading-platform` 后台管理端前端和 Java 后端代码。本文只生成文档，不提出改代码结果，不认为当前项目已经百分百实现截图功能。

## 1. 审计结论

当前项目已经搭出一套独立后台管理端，但还不是 WH 截图后台的完整复刻。

已具备的核心基础：

- 前端：`apps/admin` 是 React 19 + Vite 7 + TypeScript 管理端，运行端口为 `5174`，通过 Vite 代理访问 `localhost:8080`。
- 后端：`backend` 是 Java 21 + Spring Boot 3.5.7，数据库访问层使用 MyBatis-Plus Mapper，数据库结构由 Flyway 管理。
- 后台菜单：当前运行时 `/api/admin/features` 返回 25 个页面 key，覆盖截图中的主要菜单：权限、产品、财务、用户、订单、日志、内容、系统设置。
- 通用页面：`FeatureCrudPage` 已有搜索区、表格、分页外观、新增/编辑弹窗、导入/导出任务入口、列隐藏设置保存。
- 后端模块：已存在 `/api/admin/users`、`/api/admin/rbac`、`/api/admin/market`、`/api/admin/finance`、`/api/admin/members`、`/api/admin/trading`、`/api/admin/logs`、`/api/admin/config`、`/api/admin/table-tools` 等控制器。

主要缺口：

- 很多页面“能打开”和“业务闭环完成”不是一回事。部分页面是 `AdminFeatureCatalogService` 按截图硬编码的字段、列、静态 rows；真实数据、真实筛选、真实删除、真实编辑、真实导入导出还未完整打通。
- 前端通用 CRUD 只做浏览器本地过滤，后端大部分列表只接收 `page/size`，没有实现截图中每个搜索条件、日期范围、排序、状态筛选的服务端查询。
- RBAC 有表和接口，但菜单权限、按钮权限、数据权限尚未真正接入前端菜单渲染、路由拦截和后端 QueryService 数据范围过滤。
- 仪表盘、个人中心、消息中心、上传、富文本、表格设置、导入导出、打印、固定列、状态开关、排序步进等交互只实现了部分外观或入口，未达到截图粒度。
- 财务、订单、产品、用户模块的高风险联动还不完整，例如充值凭证、提现冻结退回、用户余额修改、后台代登录、重置密码、控盈利/控正常、挂单成交、产品倍数/费率/价格精度联动。

## 3. 当前项目后台架构现状

### 3.1 前端现状

当前后台前端不是 WH 原站的 Vue/MineAdmin/Arco 后台，而是 React 重建版。

结构：

- `AdminLayout`：左侧菜单、顶部面包屑、多标签、全屏、通知、表格设置、九宫格、退出。
- `adminMenuGroups`：静态声明菜单分组，不是后端动态菜单驱动。
- `AdminApp`：路由写死到 React Router，核心 WH 页面多数走 `FeatureCrudPage(pageKey)`。
- `FeatureCrudPage`：用后端页面配置动态渲染字段、列、工具按钮、行按钮。
- `adminApi.ts`：对一部分 `pageKey` 改走真实领域接口，另一部分回退到 `/api/admin/features/{pageKey}` 目录页。

前端已经具备：

- 左侧菜单分组。
- 多标签打开和关闭。
- 面包屑。
- 通用搜索表单。
- 通用表格。
- 通用弹窗。
- 表格列隐藏、大小、边框、斑马纹的本地配置并调用后端保存。
- 新增/编辑/删除/导入/导出/展开等按钮外观。

前端缺少：

- 与截图一致的 WH 视觉细节：logo、头像、时间卡片、统计卡片、背景图、右侧固定操作列阴影、树表、抽屉式菜单编辑、时间线日志。
- 真实动态菜单：当前菜单是静态数组，不按角色菜单权限从后端生成。
- 按钮权限：按钮显示不按角色按钮权限控制。
- 数据权限感知：前端不会根据角色数据范围隐藏或限制筛选。
- 服务端搜索：`FeatureCrudPage` 的搜索只是 `String(row[key]).includes(...)` 本地过滤，不会把筛选条件提交给后端。
- 真实分页：通用页面的分页只是展示“共 N 条 / 1 / 10 条/页”，没有页码状态和服务端分页联动。
- 表格固定列、列宽拖拽、列排序、本页/服务器排序、打印、刷新保留筛选、横向滚动同步。
- 富文本编辑器、上传组件、图片预览、密码眼睛切换、状态 switch、排序步进器、菜单树选择器、角色权限树。
- 导入导出真实文件处理：前端只创建任务，没有上传真实文件、下载文件、任务进度、失败行反馈。

### 3.2 后端现状

后端技术栈：

- Java 21
- Spring Boot 3.5.7
- Spring Security
- MyBatis-Plus 3.5.12
- PostgreSQL
- Flyway
- Hutool
- Lombok
- Knife4j

后端分层：

- Controller：接收参数、鉴权、统一 `ApiResponse`。
- Service：业务逻辑、事务、审计。
- Repository：MyBatis-Plus `FxBaseMapper`。
- Entity/DTO：实体和响应请求 DTO 分离。
- Flyway：所有表结构由 `V*__*.sql` 维护。

后端已经具备：

- 管理员登录和 ADMIN 角色保护。
- 用户状态、KYC、风险等级、备注、强制退出审计入口。
- RBAC 表：角色、菜单、角色菜单权限、用户角色、部门、岗位、角色数据范围。
- 产品分类、产品状态、价格调整记录。
- 支付方式、人工入金/出金/余额调整、资金审核订单。
- 会员资料、KYC 申请、用户银行卡/钱包。
- 订单查询、持仓查询、成交查询、后台撤单、强制平仓。
- 资金流水、请求日志、验证码日志。
- 站内消息、公告/新闻、字典、系统设置。
- 表格列偏好、导出任务、导入任务、批量任务。

后端缺少：

- 大多数列表的多条件查询对象。当前许多 Controller 只收 `page`、`size`。
- 统一服务端排序、筛选、日期范围、模糊搜索、精确匹配。
- 数据权限统一注入机制，例如按部门、本人、本部门及以下限制查询。
- 菜单权限和按钮权限对 Controller/Service 的细粒度鉴权。
- 与截图字段一一对应的数据模型，例如后台管理员头像、所属部门、岗位、角色多选、产品倍数、默认倍数、每手、费率、充值凭证、提现收款快照、用户邀请码、上级 ID、登录失败次数、实名图片、后台个人中心资料等。
- 真实删除/软删除/恢复/回收站体系。
- 文件上传、附件表、上传模式配置实际生效。
- 富文本内容 XSS 白名单处理和富文本资源管理。
- 邮箱/短信配置对真实验证码发送链路的动态影响。
- 导入导出任务处理器，没有生成实际 Excel/CSV 文件。
- 后台请求日志拦截器与所有请求的完整采集仍需验证和补全。

## 4. 页面与功能逐项缺口

下面按截图菜单逐页说明。状态说明：

- 已具备：当前前端和后端已经有主要能力。
- 部分具备：有页面或接口，但字段、联动、权限、数据源不完整。
- 缺失：当前项目没有对应页面、接口或业务闭环。
- 静态目录：后端或前端只是按截图配置了字段/示例行，不等于真实业务数据。

### 4.1 全局框架

目标功能：

- WH 风格左侧菜单、顶部栏、多标签、面包屑、右上角全屏/通知/头像/九宫格。
- 菜单折叠，标签左右滚动，标签关闭，路由切换时激活状态同步。
- 表格工具栏含刷新、搜索、打印、设置。

当前实现：

- `AdminLayout` 有左侧菜单、面包屑、多标签、全屏、通知、表格设置、九宫格、退出。
- `adminMenu.ts` 静态维护菜单。
- `FeatureCrudPage` 有刷新、设置按钮，部分按钮有图标。

缺口：

- 没有 WH 截图中的真实 logo、头像图片、头像菜单、通知弹窗、九宫格应用面板。
- 标签栏没有截图中大量标签时的左右滚动按钮和关闭左侧/右侧/其他。
- 表格搜索图标、打印图标没有真实功能。
- 菜单折叠只缩窄文字，不是 WH 的完整折叠交互。
- 页面权限不由后端菜单返回驱动。
- 后端 RBAC 菜单表没有真正驱动前端菜单。

补全重点：

- 将 `adminMenuGroups` 改为“后端菜单树 + 本地路由组件注册表”的组合。
- 在登录后加载 `/api/admin/rbac/menus`、当前用户角色和按钮权限。
- 顶部头像与当前管理员资料绑定，通知数从消息接口读取。
- 表格工具抽成复用组件，真正支持刷新、显示/隐藏搜索、打印、设置。

### 4.2 仪表盘

目标功能：

- 欢迎区：头像、用户名、欢迎文案。
- 时间卡片：每秒刷新时分秒和日期。
- 统计卡片：用户、真实用户、体验用户、充值、提现、订单，各自显示总数和新增。
- 趋势图：按日期展示统计折线。

当前实现：

- `DashboardPage` 调用 `/api/admin/dashboard/summary`。
- 后端 `AdminDashboardService` 返回用户、账户、订单、待处理订单、持仓、打开持仓、成交、流水、品种、审计数量。

缺口：

- 没有 WH 的欢迎区、当前管理员头像、用户名。
- 没有时间卡片。
- 没有“真实用户/体验用户/充值订单/提现订单/新增数”的指标。
- 没有趋势图数据接口，也没有图表组件。
- 指标命名偏交易平台通用摘要，不是截图的业务口径。
- 后端统计 `pendingOrderCount` 和 `openPositionCount` 使用查询列表后 `size()`，不是数据库 count 条件查询，数据大时不适合。

补全重点：

- 新增 dashboard DTO：用户总数、新增用户、真实用户、体验用户、充值总数/新增、提现总数/新增、订单总数/新增、7 日趋势。
- 增加 `GET /api/admin/dashboard/trends?from&to&granularity=day`。
- 前端增加 WH 风格卡片和折线图组件。

### 4.3 个人信息与消息中心

目标功能：

- 个人信息页面：顶部背景图、头像本地上传、个人资料、安全设置、登录日志、操作日志。
- 个人资料字段：账户名、昵称、手机、邮箱、个人签名。
- 安全设置字段：旧密码、新密码、密码强度、确认密码。
- 消息中心：收件箱、已发送、私信、公告、通知等分类，支持搜索、重置、发私信、删除、标记已读。

当前实现：

- 当前菜单没有 `个人信息`、`消息中心` 路由。
- 登录页只有邮箱和密码。
- 后端有 `content.messages` 和 `/api/admin/content/messages`，但作为内容消息管理，不是当前管理员个人消息中心。
- 后端有 audit logs，但没有个人登录日志和个人操作时间线接口。

缺口：

- 完整缺失个人中心 UI。
- 缺失管理员个人资料表和接口。
- 缺失头像上传、签名、手机邮箱修改。
- 缺失修改密码接口在后台个人中心中的使用。
- 缺失登录日志表或对 `auth.user_devices` 的后台展示聚合。
- 缺失操作日志时间线筛选当前管理员。
- 缺失 WH 消息中心页面和消息读/未读、发私信、收件/发件/抄送/待办分类。

补全重点：

- 新增 `/profile`、`/messages` 前端路由。
- 后端新增 `AdminProfileController`，复用认证用户表并扩展管理员资料。
- 后端新增 `AdminMessageCenterController`，区分管理员个人消息与会员通知。
- 登录日志、操作日志从审计和请求日志聚合，按当前管理员过滤。

### 4.4 权限：后台用户管理

目标功能：

- 部门树筛选、搜索部门、折叠。
- 搜索：账户、手机、邮箱、状态、注册时间。
- 工具：新增、删除、导入、导出。
- 表格：头像、账户、昵称、手机、邮箱、状态开关、注册时间。
- 编辑：头像、账户、密码、角色、岗位、所属部门、昵称、手机、邮箱、状态、备注。
- 角色/部门/岗位联动权限。

当前实现：

- 前端菜单有 `/system/users`，但 `adminApi.ts` 没有对 `system-users` 改走真实后台用户接口，默认使用 `/api/admin/features/system-users`。
- 后端目录里 `system-users` 有截图字段和两条静态示例 row。
- 真实 `/api/admin/users` 管理的是 `auth.users` 交易用户/管理员基础账号，字段为 email、phone、status、role、kycStatus、riskLevel、createdAt。
- `AdminUserService` 支持状态、KYC、风险等级、备注、强制退出，但不支持新增后台用户、编辑角色部门岗位、头像、导入导出。

缺口：

- `system-users` 页面当前是静态目录，不是真实后台管理员列表。
- 没有后台管理员专用资料模型：账号名、昵称、头像、部门、岗位、角色多选、备注。
- 没有新增后台管理员接口。
- 没有编辑后台管理员接口。
- 没有后台用户密码重置接口。
- 没有部门树筛选和部门数据权限联动。
- 没有状态 switch 即时更新。
- 导入导出只是任务入口，未导入真实文件或导出真实账号。
- 删除没有实际删除后台用户，也没有防止删除超级管理员/当前账号的规则。

补全重点：

- 在现有 `admin` schema 下新增或扩展后台管理员资料表，仍保留 `auth.users` 作为登录主体。
- `AdminRbacService` 的用户角色表要接入后台用户编辑。
- 前端 `system-users` 改为真实接口，字段按截图补齐。
- 新增部门树组件，部门筛选传入后端。

### 4.5 权限：角色管理

目标功能：

- 搜索角色名称、角色标识、状态、创建时间。
- 表格排序步进、状态开关。
- 菜单权限树：展开/折叠、全选/全不选、关闭父子级联、过滤菜单。
- 数据权限：全部、自定义、本部门、本部门及以下、本部门及以下按数据表部门 ID、本人。
- 角色编辑：名称、标识、排序、状态、备注。

当前实现：

- 前端 `system-roles` 改走 `/api/admin/rbac/roles`。
- 后端有 `admin.roles`、`role_menu_permissions`、`role_data_scopes` 表。
- `AdminRbacController` 支持角色创建、菜单权限保存、数据范围保存。

缺口：

- 前端 `getSystemRolesFeaturePage` 只暴露新增动作，`rowActions` 为空，覆盖掉后端目录里的菜单权限/数据权限/编辑/删除。
- 角色编辑、删除、状态开关、排序步进没有真实前端操作。
- 菜单权限弹窗树没有实现。
- 数据权限弹窗没有实现。
- 后端 `role_data_scopes` 只是保存，不参与任何列表查询。
- 后端没有角色更新、删除、状态切换接口。
- 没有超级管理员保护规则。

补全重点：

- 前端保留真实数据源，同时恢复 WH 角色行操作：菜单权限、数据权限、编辑、删除。
- 后端补 `PUT /roles/{id}`、`DELETE /roles/{id}`、`PATCH /roles/{id}/status`、`PATCH /roles/{id}/sort`。
- QueryService 统一接入数据权限过滤。

### 4.6 权限：部门管理

目标功能：

- 部门树表、展开/折叠。
- 搜索部门名称、负责人、手机、状态、创建时间。
- 新增、删除、领导列表、编辑、状态开关、排序步进。

当前实现：

- 前端 `system-departments` 改走 `/api/admin/rbac/departments`。
- 后端有 `admin.departments` 表和创建接口。

缺口：

- 前端真实部门页只有新增，行操作为空。
- 后端没有部门更新、删除、状态切换、排序、领导列表接口。
- 没有树结构渲染和父子删除校验。
- 用户所属部门未与后台用户管理真实联动。
- 数据权限没有引用部门树。

补全重点：

- 部门实体补负责人绑定策略：文本或后台用户 ID。
- 增加树查询接口和更新/删除/排序/状态接口。
- 前端树表支持展开、折叠、子节点缩进。

- 前端 `news` 未改走真实文章接口。
- 后端缺图片、链接字段。
- 图片上传和预览缺失。
- 链接协议校验缺失。
- 编辑、删除缺失。

补全重点：

- 扩展文章表或新增内容附件字段。
- 新闻和公告共用内容服务，但通过 articleType 区分。

### 4.23 内容：通知表

目标功能：

- 搜索用户 ID、创建人、创建时间。
- 新增、编辑、删除。
- 表格：用户 ID、内容、创建人、创建时间、更新时间。
- 内容可包含 HTML。

当前实现：

- `member-notices` 默认走静态目录。
- 后端 `content.messages` 可以发送给 targetUserId。

缺口：

- 前端未改走真实消息接口。
- 后端没有按创建人/用户/时间筛选。
- 编辑、删除缺失。
- 富文本编辑缺失。
- HTML XSS 过滤缺失。
- 推送/已读状态未实现。

补全重点：

- 会员通知走 `content.messages` 或单独 `member_notices`，必须明确读写和推送状态。

### 4.24 系统设置：站点配置

目标功能：

- 页签：站点配置、上传配置、短信配置、邮箱配置、底部导航。
- 站点字段：网站名称、关键字、描述、版权、备案、PC 邀请链接、WS 链接、充值费率、手动休市、平仓手续费、提现费率、下单手续费、客服链接、手机端邀请链接、后台登录前端链接、投诉邮箱。
- 提交、重置。
- 右上角新增配置和管理配置。
- 配置影响业务：费率、休市、WS、客服、邀请链接。

当前实现：

- `settings-*` 默认走静态目录。
- `AdminFeatureOperationService` 对 `settings-*` 的 submit/edit 会逐项 upsert 到 `config.system_settings`。
- 后端有 `/api/admin/config/settings`。

缺口：

- 页面显示的是截图目录中的单行静态配置，不是从 `system_settings` 按组动态生成字段值。
- 重置只是通用动作，没有恢复后端原值。
- 新增配置组、管理配置列表没有完整前端。
- 费率、休市、WS、客服、邀请链接没有实际接入业务服务。
- 密码/授权码未脱敏。
- 配置项组件类型、排序、说明没有真实动态表单。

补全重点：

- 建立配置分组和配置项模型，或规范 `settingKey` 前缀。
- 系统业务服务读取配置时走统一 `SystemSettingService`，不能只保存文本。

### 4.25 系统设置：上传配置

目标功能：

- 上传模式、本地/OSS。
- 文件类型、图片类型。
- 影响头像、凭证、新闻图片、证件图上传校验。

当前实现：

- 有静态字段和系统设置保存能力。

缺口：

- 没有上传接口。
- 没有附件表。
- 没有本地/OSS 存储策略。
- 没有前端上传组件接入。
- 没有文件类型后端校验。

补全重点：

- 新增 `UploadController` 和附件表。
- 上传配置必须被后端校验读取。

### 4.26 系统设置：短信配置、邮箱配置

目标功能：

- 短信：是否真实发送、短信宝账号、密码。
- 邮箱：端口、服务器、发送人、是否真实发送、授权码、账号。
- 影响注册、找回密码、验证码发送。

当前实现：

- 有静态字段和系统设置保存能力。
- 有验证码日志表。

缺口：

- 短信/邮件发送服务是否读取这些配置未实现。
- 没有真实发送开关的业务接入。
- 没有配置校验、测试发送按钮。
- 授权码/密码没有脱敏展示和加密存储。

补全重点：

- 增加配置读取缓存和敏感配置加密。
- 验证码服务按配置决定模拟发送/真实发送，并写发送日志。

### 4.27 系统设置：底部导航

目标功能：

- 富文本编辑 MSB 证书、服务条款。
- 保存后前台展示。

当前实现：

- `settings-footer` 有 `richtext` 字段类型，但前端 `FieldControl` 把 richtext 当 textarea。

缺口：

- 没有富文本编辑器。
- 没有资源选择器。
- 没有 HTML 白名单和 XSS 处理。
- 没有前台页面联动。

补全重点：

- 前端接入富文本组件。
- 后端保存富文本前做 XSS 白名单清洗。

## 5. 横切能力缺口

### 5.1 查询、分页、排序

当前问题：

- 通用页面本地过滤，服务端不知道筛选条件。
- 多数 Controller 只收 `page/size`。
- 日期范围、下拉选项、状态映射没有统一请求模型。
- 表格列排序只是视觉箭头。

需要补齐：

- 每个列表建立 Query DTO。
- `AdminPageRequests` 支持 sortField、sortDirection，字段白名单防 SQL 注入。
- Repository 用 MyBatis-Plus `LambdaQueryWrapper` 拼接条件。
- 前端搜索提交后重置页码为 1，分页变化重新请求。

### 5.2 新增、编辑、删除、状态、排序

当前问题：

- 很多页面的 `create/edit/delete` 只是写 `admin.feature_records` 或创建任务，并不修改真实业务表。
- 状态开关没有统一组件和接口。
- 排序步进没有真实保存。

需要补齐：

- 每个页面明确真实业务表。
- 每个高风险动作有 DTO、Service、事务、审计。
- 删除区分禁止删除、软删除、恢复、真实删除。
- 排序改动使用专用接口并支持防抖保存。

### 5.3 RBAC 和数据权限

当前问题：

- RBAC 表存在，但未驱动菜单和按钮。
- 数据范围保存存在，但未限制查询。
- Controller 只有 `hasRole('ADMIN')` 粗粒度限制。

需要补齐：

- 登录后返回当前管理员菜单树和按钮权限。
- 前端按权限渲染菜单和按钮。
- 后端细粒度校验权限码。
- QueryService 根据角色数据范围自动追加条件。

### 5.4 上传、图片、富文本

当前问题：

- 上传区域、凭证、头像、证件图片、新闻图片都未形成统一上传能力。
- `richtext` 只是 textarea。

需要补齐：

- 文件上传接口、附件表、存储适配器、本地/OSS 配置。
- 图片预览、删除、回显。
- 富文本编辑器、资源选择器、XSS 处理。

### 5.5 导入导出

当前问题：

- 后端有 `export_tasks`、`import_tasks`、`batch_operations` 表。
- 前端导入/导出只创建任务，没有真实文件。

需要补齐：

- 导出任务处理器生成 Excel/CSV。
- 导入上传文件、解析、校验、失败行报告。
- 前端显示任务状态、下载地址、错误明细。

### 5.6 审计与请求日志

当前问题：

- 多数写操作有审计日志。
- 请求日志表存在，但字段缺请求用户/用户名，列表筛选不足。

需要补齐：

- 全局请求日志拦截器记录用户、IP、路径、参数摘要、响应码、耗时。
- 高风险操作必须二次确认并写审计详情。
- 日志删除高权限限制。

## 7. 补全优先级建议

P0，必须先补：

- 服务端查询、分页、排序基础能力。
- RBAC 菜单/按钮权限接入前后端。
- 数据权限作用于用户、订单、财务、日志查询。
- 后台用户真实 CRUD、角色/部门/菜单/岗位真实编辑删除。
- 资金订单审核字段补全，充值/提现与资金流水一致。
- 订单聚合页真实绑定交易订单、持仓、成交。

P1，业务完整性：

- 产品列表真实绑定 `market.symbols` 并补 WH 管理字段。
- 产品风控、涨跌设置建模和行情生成联动。
- 用户列表会员扩展资料、KYC 图片、银行卡、密码、备注、发信。
- 上传、附件、图片预览、凭证和证件图片。
- 公告、新闻、通知真实绑定内容表。

P2，体验和运维：

- 仪表盘趋势图、时间卡、欢迎区。
- 个人中心和消息中心。
- 表格设置完整化：列宽、固定列、服务器排序、打印。
- 导入导出任务处理器。
- 配置管理高级功能、短信/邮箱测试发送。

## 8. 不建议的实现方向

- 不建议另起一套 Java 框架。当前 Spring Boot + MyBatis-Plus + Flyway 已经能承载扩展。
- 不建议把截图字段全部塞进一个 JSON 字段来快速展示。资金、订单、用户、权限字段需要可查询、可审计、可约束。
- 不建议用 `admin.feature_records` 承载核心业务数据。它适合作为临时目录/扩展记录，不能替代产品、订单、资金、用户等领域表。
- 不建议让前端直接决定高风险业务结果。充值、提现、平仓、撤单、控盈利等必须走后端领域服务和事务。
- 不建议把 WH 的“控盈利/控输”做成隐蔽价格控制。若业务确需模拟或测试场景，必须显式建模、权限隔离、审计可追溯。

## 9. 验收口径

后续如果要声明“当前项目百分百实现截图功能”，每个页面至少要满足：

- 页面菜单由后端权限控制可见。
- 搜索条件传到后端，能按字段、状态、日期范围筛选。
- 分页、排序、每页条数真实请求后端。
- 新增、编辑、删除、状态、排序、审核等按钮有真实接口、真实表、真实审计。
- 弹窗字段能回显、校验、保存，必填项前后端一致。
- 上传字段能上传、预览、删除、回显，并受上传配置限制。
- 富文本字段用富文本编辑器并做 XSS 处理。
- 导入导出能产生或消费真实文件，并有失败反馈。
- 高风险操作有二次确认、权限码、审计日志和幂等保护。
- 财务和订单操作能保持余额、保证金、流水、订单状态一致。
- 配置项保存后会影响对应业务，而不是只保存在配置表。
